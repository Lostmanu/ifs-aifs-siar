# Comunicar un error o proponer una corrección

El estudio está cerrado; se agradecen correcciones verificables en código, datos publicados o documentación. Una nueva hipótesis o ampliación de estaciones necesita su propio diseño.

Abra un [issue](https://github.com/Lostmanu/ifs-aifs-siar/issues) con archivo y versión, lo esperado y lo ocurrido. Para fallos de reproducción, añada sistema operativo, Python, NumPy, comando y `comprobacion_offline.json`. Puede retirar rutas personales antes de compartirlo.

Para una objeción científica, indique cifra, supuesto o inferencia y la fuente que permite contrastarla. Distinga un error numérico de una interpretación diferente.

## Conservar la trazabilidad

- Mantener los datos, informes históricos y paquetes ya publicados.
- Declarar las correcciones en [CHANGELOG.md](CHANGELOG.md), con su efecto en resultados y reproducción.
- Identificar los análisis posteriores; no reescribir la especificación congelada para hacerlos pasar por previos.
- Respetar las condiciones de las fuentes en [DERECHOS.md](DERECHOS.md).

Ejecute las [comprobaciones del clon](docs/REPRODUCIR.md) antes de proponer código. No se exige reproducir todo el paquete para corregir una errata de texto.
